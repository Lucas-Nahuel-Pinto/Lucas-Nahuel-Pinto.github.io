Harness Config

One command for both halves of the agent session: how the harness is configured and who uses which model/role. Zero half-configured sessions.

  • Agents
  • DX
  • Model governance

The pain in my QA flow

Agent configuration was reinvented every session: missing MCPs, keys copied across terminals, roles assigned "the usual way". Two machines gave different results on the same ticket, and nobody knew who decided the default model.

2 configurationstwo places, no single source

How a QA uses it

The two halves answer two different session questions. The command resolves both together and leaves an auditable trace.

QA questionWhere it gets answered
How is the session configured (MCPs, tooling, providers)?Configuration half — the command applies the harness setup in one step, with versioned defaults.
Which model and role does each agent use?Roles half — explicit role→model assignment, no guessing who runs what.
What happens if a model disappears or changes?Selector with fallback — the role falls back to a current model and the change stays visible.
How do I get back to a healthy state?Built-in defaults and help — restoring or inspecting state is part of the same command.

In my working kit

The full cheat sheet lives in the presentation; these are the orders I run daily.

bun run harness-configApplies both halves: config + roles
bun run harness-config-helpInspect current state and options
bun run harness-config-defaultRestore versioned defaults
bun run harness-config:roles:testTests for the model/role selector
  • Quality gates: role-selector tests on every flow change.
  • Reversibility: every applied state rolls back to defaults.
  • Explicit decisions: the default model is declared, never inherited by habit.

What it demonstrates

Environment automation

I turn repeated manual setups into reproducible commands with tests.

QA-facing DX

One command, built-in help and rollback: less friction between writing tests and running them.

Model governance

Explicit role→model with fallback: I know which model runs each agent and why.

Closing
