El dolor en mi flujo QA

La trazabilidad vivía repartida entre Jira, Xray y hojas de cálculo. Para saber si una historia estaba realmente cubierta había que seguir links a mano, historia por historia. Los huecos —historias huérfanas, épicos vacíos, bugs sin historia— aparecían cuando alguien los necesitaba, no antes.

2-3 horasde auditoría manual por sprint

Cómo lo usa un QA

Cada vista responde una pregunta de calidad concreta. Ninguna muestra "cómo está construido" el código: solo qué significa para el release.

Pregunta QADónde se responde
¿Qué cubre realmente cada historia?Árbol — la jerarquía Épico→Historia→ATP→ATR→TC en un vistazo, con los huecos marcados.
¿Dónde se rompe la cadena de trazabilidad?Grafo — el vínculo real entre entidades; los nodos sin conexión salen destacados.
¿Qué componentes tienen cobertura hueca?Matriz — historia × componente: celdas vacías = riesgo de release, no de código.
¿Qué está roto HOY?Alertas — historias huérfanas, épicos vacíos, bugs sin historia y bloqueadores abiertos, siempre a la vista.
¿Mejora o empeora cada sprint?Métricas — cobertura, pendientes y tendencia para decidir con datos, no con sensaciones.

En mi kit de trabajo

Una sola orden refresca el snapshot; el dashboard es un archivo estático que puedo abrir, compartir o archivar por sprint.

bun run trace:pullDescarga el snapshot de Jira/Xray
bun run trace:refreshPull + rebuild del dashboard
bun run buildConstruye la app de 5 pestañas (archivo único)
bun testPipeline con tests: validación de esquema y alertas
  • Gates de calidad: schema validado con ajv antes de renderizar, alertas como reglas testeadas.
  • Fail-safe: si el snapshot viene corrupto, el dashboard lo dice en vez de mostrar números falsos.
  • Revisión por evidencia: cada métrica se audita contra el link original, no contra una hoja de cálculo.

Qué demuestra

Trazabilidad

Sigo cada hallazgo hasta su historia y cada historia hasta su evidencia: la cadena completa, no un estado suelto.

Data-driven QA

Las decisiones de release salen de métricas y alertas reproducibles, no de la memoria del equipo.

Riesgo antes que volumen

El dashboard prioriza los huecos que rompen el release (huérfanos, vacíos, bloqueadores) sobre el conteo bruto de tests.

Cierre

De auditoría manual a una orden y 30 segundos. El repo es público (licencia MIT) y el demo corre con datos sintéticos que podés regenerar.
